# Contributing to mk4-synth

Thanks for helping! Bug reports, sound fixes, new presets and synthesis engines, and especially
**reports from builds on other ESP32-S3 boards and DACs** are all welcome (see
[Building on other hardware](#building-on-other-hardware)).

## A human summary is required

**Every issue and pull request must start with at least one sentence written by a person** (not
generated by an AI tool), in your own words. Say what you saw or what you changed, and why. Any
language is fine, and so is imperfect English. AI tools may help with the rest of the
description, the code or the investigation. But the maintainers need to know that a person
looked at the problem and stands behind the report. Issues and PRs without a human summary will
be closed. You can reopen once you add one.

The issue and PR templates have a **Summary (written by you)** field for this.

## Reporting a problem

Open an issue with:

- your human summary (see above)
- your board and parts, if they differ from [HARDWARE.md](HARDWARE.md) (ESP32-S3 module, DAC,
  OLED, how it's powered)
- the commit you built, and whether you changed anything
- the MK4's firmware version (`./build/mpk_display --identify` prints it)
- the preset number, and what you played
- for sound problems, **a short recording** or a WAV from `synth_render` that shows it. Say
  whether the desktop simulator (`synth_sim`) sounds the same, which tells us if it's the engine
  or the board.
- for crashes, freezes, stuck notes or static, the serial log from
  `python3 tools/synthctl.py capture 40` (see the README)

Please don't attach Akai firmware, Studio Instrument Collection files, or anything extracted from
them. They are Akai's copyrighted material.

## Sound and presets

The presets aim to sound and feel like the instruments they're named after.

- **"This doesn't sound like a real Juno / Minimoog / ..."**: open a *Sound or preset* issue.
  Reference recordings of the original and a recording of the preset help most. Say which
  parameter or behaviour is off (envelope shape, filter resonance, chorus, velocity response,
  ...).
- **Changing a preset or adding one**: edit `lib/SynthEngine/include/Presets.h`, run
  `make manual`, and commit the regenerated `docs/mpk_mini_mk4_manual.html`. Each preset has 16
  knob parameters (Bank A and Bank B); keep the knob layout consistent with the presets of the
  same engine.
- **Adding a synthesis engine**: open an issue first to agree on the scope. A new engine needs to
  fit the audio budget on the board with several voices sounding, so include a profiling capture
  (`make profile`, then `make capture`) if you can. Record the design in a new ADR under
  `docs/adr/`, like [ADR-0007](docs/adr/0007-additional-synthesis-engines.md).

`PresetLoudnessTest` keeps the presets at a similar level. If a change trips it, adjust the
preset rather than the test.

## Building on other hardware

Only one build has been tested so far: the reference build in [HARDWARE.md](HARDWARE.md). These
are the parts tied to it:

| What | Where | Notes |
|---|---|---|
| ESP32-S3-DevKitC-1 N16R8 (16 MB flash, 8 MB octal PSRAM) | `platformio.ini` | Other S3 modules should work if the flash and PSRAM settings match |
| PCM5102A on I2S, GPIO 4/5/6 | `I2S_*_IO` in `src/esp32s3_driver.h` | Other I2S DACs that need no I2C setup are a pin change |
| SSD1306 128x64 OLED on I2C, GPIO 8/9 | `OLED_*_PIN` in `src/oled_ui.h` | |
| MK4 on the native USB host port (GPIO 19/20) | `src/usb_host_midi.h` | The serial console is on the UART port; native USB is the host |
| Audio budget 2902 us per 128-frame block | `src/profiling.h` | Measured on 240 MHz dual-core; slower parts need fewer voices |
| Akai MPK Mini MK4 | `lib/MpkMiniMk4Display/` | The only supported controller (see below) |

A good way to start:

1. Open a **Hardware report** issue with your board, DAC and display.
2. Build with `pio run -e diag_dac_test` and the sketches in [diagnostics/](diagnostics/README.md)
   to bring up each part on its own before the full firmware.
3. Attach a profiling capture so we can see whether the audio budget holds.

Ports should keep the existing pin assignments as the default and add a new PlatformIO
environment rather than changing `esp32s3_rev2`.

**Other controllers.** The MK4's screen, knob labels and preset slots are driven over its own
SysEx protocol, which is specific to that model. Other class-compliant MIDI keyboards may play
notes, but they aren't supported, and the MPK Mini MK3 uses a different protocol.

## Development setup

You need macOS (Linux should work but isn't tested), CMake 3.16+ and a C++20 compiler. PortAudio and RtMidi are optional;
without them the simulator and `mpk_display` are skipped. PlatformIO builds the firmware.

```bash
git clone https://github.com/bydash-xyz/mk4-synth.git
cd mk4-synth
brew install cmake portaudio rtmidi       # or your distribution's packages
pipx install platformio
make test                                 # build and run the desktop tests
make firmware                             # build the ESP32-S3 firmware
```

## Pull requests

Before opening a PR:

- [ ] the description starts with your own human-written summary (see above)
- [ ] `make test` passes and the desktop build has no new warnings
- [ ] `pio run -e esp32s3_rev2` builds
- [ ] if you changed `Presets.h` or knob mappings, the manual is regenerated (`make manual`)
- [ ] if you changed the patch format, the change follows
      [ADR-0006](docs/adr/0006-parameter-list-patch-format.md): new parameter IDs only, never
      reused or renumbered, and older saved patches still load
- [ ] say how you tested: desktop tests only, simulator, or flashed to a board (which one)

Keep PRs focused. One fix or feature per PR is easier to review and to test on hardware.

Code style: follow the surrounding code. The engine in `lib/SynthEngine/` must build without
Arduino headers so it runs on the desktop and in the tests; hardware access goes through the
drivers in `src/`, which the tests mock. Comments explain *why*, usually a measured hardware or
timing quirk. [AGENTS.md](AGENTS.md) lists the invariants the firmware relies on (no locks on the
audio path, no per-event logging in the USB task, ...); please read it before changing `src/`.

## What can't be accepted

- Akai firmware, software or sample data, or files extracted or derived from them
- Samples, wavetables or other audio taken from commercial instruments or sample libraries.
  Sounds should be synthesized, or come from sources whose license allows redistribution, with
  the license noted.
- Fonts whose license doesn't allow redistribution
